# 뷰우티 대시보드

중소 화장품 브랜드의 해외영업·RA 실무자를 위한 **국가별 성분 규제 스크리닝 및 수출 준비·행정 관리 대시보드**입니다.

이미 완제품을 보유한 브랜드가 수출 대상 국가를 선택한 후, 제품의 성분 규칙과 준비 서류를 확인하고 관세·통관·시장·유통사 정보를 함께 검토하도록 돕습니다.

> **문서 상태: 설계 기준안**  
> 이 README는 팀이 합의한 목표 기능과 협업 규칙을 정리합니다. 아래 기능·API·로그인·저장·화면이 모두 구현 완료되었다는 뜻은 아닙니다. 실제 구현 상태는 기능별 PR과 각 모듈의 `readme.md`에 기록합니다.

## 1. 프로젝트 목표와 범위

- 국가별 JSON을 활용한 성분 스크리닝
- 내 제품과 관련된 규제 변경 피드
- 국가별 수출 준비 로드맵과 서류 체크리스트
- HS 코드·원산지에 따른 일반·FTA 관세율 안내
- 국가별 통관 상세 안내와 환율 계산기
- 화장품 수출입 통계와 근거 기반 유통사 후보 추천
- 로그인 계정별 프로젝트·여러 제품·분석 이력 저장

초기 범위에서 거래금액·운임·보험료·수량·거래조건을 통한 총수입비용 계산은 제공하지 않습니다. 실제 통관 진행 상태 자동 조회, 규제 JSON 자동 개정, 유통사 자동 연락도 초기 범위에 포함하지 않습니다.

## 3. 사용자 흐름과 저장 방식

1. 첫 화면에서 지도와 한국 화장품 수출통계를 확인합니다.
2. 지도 마커 또는 국가 버튼으로 목적국을 선택합니다.
3. 제품 업로드·저장을 시작할 때 로그인합니다. 선택한 국가는 유지합니다.
4. 수출 프로젝트를 만들고 제품을 하나 이상 등록합니다.
5. Tab 1에서 성분 분석과 수출 준비 상황을 확인합니다.
6. Tab 2에서 선택 제품의 관세율·통관 절차를 확인합니다.
7. Tab 3에서 시장 정보와 유통사 후보를 검토합니다.
8. 저장한 프로젝트를 다시 열어 업무를 이어갑니다.

### 저장 단위

| 단위 | 저장 내용 |
|---|---|
| 계정 | 사용자 식별·인증 정보 |
| 수출 프로젝트 | 소유 사용자, 프로젝트명, 목적국, EU 목적 회원국 등 |
| 제품 | 제품명·유형·성분·함량·HS 코드 등 |
| 분석 이력 | 입력 당시 성분표, 결과, 분석 시각, 규제 JSON 버전 또는 해시 |
| 업무 상태 | 제품별 로드맵 체크, 서류 준비 상태, 메모 |
| 관심 정보 | 사용자가 저장한 유통사·기사·규제 공지 |

- 하나의 국가별 프로젝트에 여러 제품을 저장할 수 있습니다.
- 같은 제품을 재분석하면 이전 결과를 덮어쓰지 않고 새 분석 이력을 만듭니다.
- 다른 국가로 수출할 때는 제품을 복사해 별도 프로젝트를 만듭니다.
- 과거 분석은 당시 기준을 보존합니다. 최신 피드 수집이 과거 판정 결과를 자동 변경하지 않습니다.
- 로그인·소유권 검증·DB 저장은 공통 플랫폼 담당자가 구현합니다.
- 팀 개발용 GitHub 저장소와 서비스 사용자의 제품 저장 DB는 별개입니다. 실제 제품 처방·함량은 Git에 올리지 않습니다.

## 4. 디자인 방향

### 첫 화면

첫 번째 디자인 레퍼런스의 **밝은 라벤더·화이트, 큰 지도 또는 지구본, 주변 통계 카드**를 참고합니다.

- 질문: **어디로 수출하겠습니까?**
- 한국에서 8개 목적지로 이어지는 곡선·이동 효과
- 국가 마커에 마우스를 올리면 국가명·관련 수출 요약 표시
- 국가 클릭 시 해당 국가 대시보드로 이동
- 지도 아래에 국가 선택 버튼도 제공
- 주변 카드: 한국 화장품 총수출액, 전년 동기 대비 성장률, 주요 수출 대상국, 수출 추이
- 통계에는 집계 기간·단위·출처 표시

Portflow 활용은 검토 대상입니다. 정확한 도구·링크 및 구현 가능 범위를 확인한 뒤 지도 기술을 확정합니다.

### 국가별 대시보드

두 번째 레퍼런스의 **상단 둥근 탭과 가로 타임라인 형식**을 참고하되, 색상은 첫 화면과 통일합니다.

- 상단: 국가 선택으로 돌아가기, 3개 탭, 저장 상태, 내 프로젝트, 계정
- 본문 상단: 프로젝트명, 선택 국가, 제품 선택, 제품 추가
- Tab 1 상단에 별도 KPI 요약 카드를 추가하지 않음
- 공통 레이아웃·디자인 토큰은 플랫폼 담당자가 관리

| 용도 | 기준 색상 |
|---|---|
| 전체 배경 | `#F5F4FA` |
| 카드 | `#FFFFFF` |
| 주요 버튼·활성 탭 | `#8870E8` |
| 보조 강조 | `#EEE9FC` |
| 제목·본문 | `#302B54` |
| 경계선 | `#E6E3EF` |

판정 상태는 색상과 텍스트를 함께 표시합니다. `해당 없음`은 중립적인 회색으로 표현합니다.

### 로드맵 디자인

가로 선 위에 주요 단계의 원형 노드, 아래에 서류·세부 작업 노드를 연결합니다. 현재 단계는 보라색, 완료 단계는 연보라색과 체크, 미시작 단계는 회색으로 표시합니다.

단계를 클릭하면 서류 체크리스트·예상 기간·공식 링크가 펼쳐집니다. 일정 정보가 없는 데이터에 임의 날짜를 부여하지 않습니다. 국가별 작업 수를 그대로 보여주거나 큰 단계 아래 묶을 수 있으며, 원본 작업을 4개로 강제 축소하지 않습니다.

## 5. Tab 1 — 규제·수출 준비

### 화면 구성

- 왼쪽: 성분별 스크리닝 및 로드맵·서류 체크리스트
- 오른쪽: 내 제품 관련 규제 변경 피드 및 시장 요약 3개
- 상단 요약 카드 없음

### 입력

- 목적국
- 제품명·제품 유형 및 규칙 적용에 필요한 사용 정보
- 성분 CSV 또는 직접 입력한 성분 리스트
- CAS·INCI 등 식별 정보
- 배합 한도 판단에 필요한 최종 제품 내 함량(%)

CSV의 성분명에 쉼표가 있으면 CSV 인용 규칙을 적용합니다. 직접 입력에서는 `1,2-Hexanediol`과 같은 이름을 보존하도록 단순 쉼표 분리를 피하고, 한 줄에 한 성분 입력을 기본으로 합니다.

### 판정 흐름

1. 해당 국가의 규제 JSON을 읽습니다.
2. CAS를 우선 활용하고 성분명·동의어 매핑으로 보완합니다.
3. prohibit 규칙의 제품 범위·용도·예외 조건을 확인합니다.
4. 적용되는 금지 조건에 해당하면 부적합으로 판정합니다.
5. 금지되지 않은 성분은 restrict의 배합 한도·사용 조건을 확인합니다.
6. 결과와 적용 근거를 표에 표시합니다.

| 조건 | 표시 결과 |
|---|---|
| 적용되는 prohibit 금지 조건에 해당 | **부적합** |
| 적용되는 restrict 배합 한도·사용 조건 위반 | **부적합** |
| 적용되는 restrict 조건 충족 | **적합** |
| JSON에서 일치하는 적용 항목을 찾지 못함 | **해당 없음** |
| 일치한 규칙은 있으나 함량·제품 정보·조건 해석이 부족 | **확인 필요** |

`해당 없음`은 등록된 데이터에서 항목을 찾지 못했다는 표시이며 사용 승인이나 안전성 보증이 아닙니다. 성분 식별에 실패해 항목을 찾지 못한 경우도 화면 판정은 합의한 대로 `해당 없음`으로 통일하되 입력명과 매칭 정보를 보존합니다.

**규칙 파일 자체가 비어 있거나 누락·손상된 경우에는 일반적인 ‘목록 미일치’로 처리하지 않습니다.** 데이터 준비 상태 또는 로딩 오류를 표시합니다.

- `max_concentration: null`을 0이나 무제한으로 취급하지 않습니다.
- 성분군 합계량, 단위 변환, 예외 성분, 용도·제품별 제한을 단순 개별 함량 비교로 대체하지 않습니다.
- 자연어로만 적힌 조건을 자동으로 확정할 수 없으면 `확인 필요`로 남깁니다.

### 결과 표

**성분명(INCI) / 배합량(%) / 규제 유형 / 판정 결과 / 상세 조건**

표 하단 문구:

- 일본: **스크리닝은 등록된 규제 일본 후생노동성 「Standards for Cosmetics」기준입니다.**
- 다른 국가: **스크리닝은 등록된 규제 oo 기준입니다.**

다른 국가의 `oo`는 추후 담당자가 출처 문구로 교체합니다. 데이터 버전 또는 기준일도 별도로 표시합니다.

### 여러 제품의 분석표

- `+ 제품 추가`, `전체 제품 / 제품별 보기` 제공
- 같은 탭에서 제품별 분석 카드를 여러 개 저장·조회
- 각 카드에 제품명·분석일·규제 데이터 버전 표시
- 펼치기·접기, 수정 후 재분석, 분석 이력 제공
- 로드맵·체크 상태는 제품별로 분리

### 내 제품 관련 규제 변경 피드

JSON에 최신 개정을 즉시 반영하기 어려운 점을 보완하기 위해, 판정 기준과 별도로 최신 변경 공지를 제공합니다.

수집 방식: **API + RSS + 허용된 공식 게시물 수집**

| 매칭 유형 | 기준 |
|---|---|
| 성분 관련 | 제품에 입력된 전체 성분과 성분군 |
| 제품 유형 관련 | 스킨케어·립·선케어 등 유형 |
| 공통 행정 관련 | 등록·신고·라벨·서류 요건 |

기존 JSON에 등재된 성분만 감시하지 않고 사용자가 입력한 전체 성분을 매칭 대상으로 삼습니다.

카드에는 제목, 관련 이유, 핵심 내용, 개정안·확정·시행 상태, 확인된 시행일·유예 종료일, 공식 원문 링크를 표시합니다. 불확실한 관련성은 ‘관련 가능성’으로 구분하며 원문에 없는 날짜나 의무를 생성하지 않습니다.

규제 피드의 마지막 수집 시각과 스크리닝 데이터 기준일을 구분합니다. 첫 버전에서 자동 JSON 개정은 구현 범위 밖이며, 향후 검토한 규칙으로 JSON을 교체·보완할 수 있는 구조로 설계합니다.

### 수출 준비 로드맵

국가별 JSON의 단계·작업·필요 서류·필수 여부·예상 기간·공식 링크를 표시합니다. `estimated_days`가 `null`이면 **기간 확인 필요**로 표시합니다.

기존 일본 로드맵의 `required_doc` 문자열을 읽을 수 있도록 지원합니다. 개별 문서 체크가 필요하면 문서 배열로 구조화하며, 괄호 안의 쉼표까지 임의로 분리하지 않습니다. 완료 상태는 원본 JSON과 별도로 저장합니다.

### 국가시장 요약

- 해당 국가 화장품 수입액
- 수입액 성장률
- 한국산 수입 점유율

Tab 3가 제공하는 지표를 사용하며 데이터를 복제하지 않습니다.

## 6. Tab 2 — 관세·통관

### 기본 조회

입력: **목적국 / 원산지 / HS 코드**

제공 내용:
- 품목명·목적국 세부 코드
- 일반 적용 관세율과 FTA 협정세율
- 적용 협정·원산지 요건·필요 증빙
- 기준일·공식 출처

기능은 **FTA 관세율 조회·비교**입니다. 거래 금액이 없으므로 관세액이나 총수입비용을 계산하지 않습니다. 목적국 세부 품목 선택이 필요하면 추가 선택을 제공합니다.

한국에서 발송했다는 이유만으로 한국산 원산지 요건 충족을 가정하지 않습니다. 협정세율은 조건 충족 시 적용 가능하다는 안내와 함께 표시합니다. 조회 실패·미지원·협정 없음과 실제 0%를 구분합니다. 조회 기준일은 별도 기본 입력 없이 화면에 표시합니다.

### 통관 상세 안내

기본 흐름: **한국 수출신고 → 선적·운송 → 현지 수입신고 → 검사·세금 납부 → 반출**

국가별로 단계, 할 일, 필요 서류, 담당 주체, 공식 안내·신고 링크를 제공합니다. Tab 1은 전체 수출 준비, Tab 2는 통관 상세 업무를 담당합니다.

### 환율 계산기

기준 통화·대상 통화·환산 금액을 입력하고 결과, 적용 환율, 기준 시각을 표시합니다. 환율 API는 후속 연결합니다. 지원하지 않는 통화와 환율 누락을 명확히 표시합니다.

## 11. 주요 지표 산식

### 수입액 또는 수출액 성장률

`성장률(%) = (당기 금액 - 전기 금액) / 전기 금액 × 100`

같은 국가·품목·단위·기간 길이로 비교합니다. 전기 값이 0이거나 누락이면 계산 불가로 표시합니다. 연간 값과 일부 월 누계 값을 직접 비교하지 않습니다.

### 한국산 수입 비중

`한국산 비중(%) = 대상국이 보고한 한국산 화장품 수입액 / 대상국이 보고한 전체 화장품 수입액 × 100`

분자·분모의 보고국·기간·품목 범위를 일치시킵니다. 한국이 보고한 수출액을 분자로 혼용하지 않습니다. 전체 수입액이 0이거나 누락이면 계산 불가로 표시합니다.

### 한국의 대상국향 수출액

한국이 보고한 해당 목적국향 화장품 수출액입니다. 상대국 보고 수입액과 값이 다를 수 있으므로 별도 지표로 유지합니다.

### 환율 환산

각 환율을 동일 기준 통화에 대한 ‘1통화 단위 가격’으로 정규화한 후:

`환산 금액 = 입력 금액 × 기준 통화 환율 / 대상 통화 환율`

100단위 고시 등 단위 차이를 반영하고, 이전 영업일 자료 사용 시 실제 기준일을 표시합니다.

아래는 실행 진입점과 환경변수 로딩을 구현한 뒤 사용할 **목표 실행 절차**입니다. 현재 문서만으로 완성 앱이 실행되는 것은 아닙니다.

```bat
python -m venv junior
.\junior\Scripts\activate.bat
python -m pip install -r requirements.txt
if not exist .env copy .env.example .env
python -m flask --app app run --debug
```

기존 `.env`가 있으면 복사로 덮어쓰지 않습니다. 루트 의존성 파일은 각 모듈의 `requirements.txt`를 참조하도록 구성합니다. `--debug`는 로컬 개발에서만 사용합니다.

`uploads/`와 `instance/`는 실행 데이터용이며 Git에서 제외합니다. 배포 시 영속 DB·파일 저장 위치를 별도로 정해야 하며, 일시적인 로컬 디렉터리만으로 사용자 저장을 보장하지 않습니다.
